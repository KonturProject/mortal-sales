# Бэкенд Mortal Sales (Google Apps Script + Google Таблица)

Standalone-проект (не привязан к таблице через меню Extensions — открывает её по ID напрямую). Таблица — единственный источник
правды, её вкладки читаются человеком; вся работа идёт через админку, руками в таблице ничего менять не нужно (но можно).

## Развёртывание (один раз)

Делается в **новой** таблице и **новом** скрипте — ничего общего с «Отделами против дракона».

1. Создайте пустую Google Таблицу, скопируйте её ID из адреса (`.../spreadsheets/d/<ID>/edit`).
2. В таблице **Расширения → Apps Script** (скрипт привязан к таблице — из-за этого появится меню). Вставьте содержимое `Code.gs` (вместо файла по умолчанию),
   в начале замените `REPLACE_WITH_NEW_SPREADSHEET_ID` на ID таблицы.
3. **Настройки проекта (⚙) → «Показывать файл манифеста appsscript.json в редакторе»**, вставьте содержимое `appsscript.json` (часовой пояс Москва, доступ Web App).
4. Обновите страницу таблицы: появится меню **Mortal Sales**. **1. Подготовить таблицу** — Google один раз попросит разрешение (для непроверенного скрипта:
   «Дополнительно → Перейти на страницу … (небезопасно) → Разрешить»), после чего повторите пункт. Создадутся вкладки `Команда`, `Подразделения`, `Пары`,
   `Снимки`, `Дни`, `Настройки` с заголовками и начальными строками.
   (Функции с `_` в конце, `setup_` и `setAdminPin_`, в списке запуска редактора не показываются — поэтому нужно меню.)
5. PIN: меню **Mortal Sales → 2. Задать PIN администратора** — введите 4–12 цифр в окне Google (в таблице и коде PIN не хранится — только солёный хеш в
   Script Properties). Дальше PIN меняется из админки; забытый — снова через это меню.
6. **Deploy → New deployment → Web app**: Execute as **Me**, Who has access **Anyone**. Скопируйте URL вида `https://script.google.com/macros/s/XXXX/exec`.
7. Впишите URL в `game/public/config.json` (`appsScriptUrl`) и поставьте `"useMock": false`.
8. Откройте админку (`admin.html`), войдите по PIN → вкладка **«Доступ» → «Создать ключ экрана»**: получите ссылку для офисного экрана.
   Откройте её на экране один раз — ключ запомнится в браузере. Без ключа данные не отдаются (в них имена сотрудников).
9. Вкладка **«Сотрудники» → «Импорт справочника из файла»**: загрузите файл «кто в каком подразделении» (формат ниже).
10. При любой правке `Code.gs`: **Deploy → Manage deployments → ✏️ Edit → Version: New version → Deploy** (URL не меняется).

## Вкладки таблицы

Порядок колонок важен, названия — нет. Колонки не переставляйте; лишние вкладки и колонки правее таблиц не мешают.

| Вкладка | Колонки | Что это |
|---|---|---|
| `Команда` | ФИО · Подразделение · Активен · За день · За неделю до сегодня | один ряд на менеджера; «Активен» = ИСТИНА/ЛОЖЬ (также «нет», «0») |
| `Подразделения` | Код · Название · РГ · Звёзды · Побед · Поражений · Ничьих | шесть кодов СР1/2/3/5/6/9 (по числу героев) |
| `Пары` | № · Слева · Справа | кто с кем дерётся (до 3 пар) |
| `Снимки` | Импорт · Время · День · ФИО · Подразделение · Счетов · Изменение | история каждой загрузки, только добавляется |
| `Дни` | День · Неделя · № в неделе · Время · Подразделение · Счетов · Людей · Среднее · Пара · Итог · Звёзды после | завершённые дни |
| `Настройки` | Ключ · Значение | счётчики и состояние недели (PeriodId, DayIndex, DayId, ImportSeq, DaysPerPeriod, …) |

Строки таблицы никогда не удаляются целиком — только очищаются ячейки.

## Как считается бой

Исход пары и бой на экране определяет **среднее число счетов на одного активного сотрудника**: сумма счетов подразделения за день / число активных менеджеров.
Рейтинг менеджеров на экране — в абсолютных числах. «Завершить день»: побеждает тот, у кого выше среднее; победитель получает звезду (звезда = выигранный день, до 5); ничья звёзд не меняет;
после последнего дня недели матч пары выигрывает тот, у кого больше звёзд (при равенстве — выше среднее за неделю). Неактивные сотрудники в штат не входят.

## API

Один URL. `GET ?key=<ключ экрана>` — публичные агрегаты для экранов (неделя, пары, подразделения: звёзды/штат/суммы, менеджеры, последняя загрузка, команды анимаций,
`serverNow`); без верного ключа — `{ok:false, error:'display_key_not_set'|'bad_display_key'}`. Ответ кэшируется на 10 с, любая запись кэш сбрасывает.

`POST` (тело — JSON, отправляется как `text/plain`, чтобы не было CORS-preflight) — все действия требуют `pin` в теле:

| `action` | Параметры | Что делает |
|---|---|---|
| `login` | — | проверяет PIN |
| `changePin` | `newPin` | меняет PIN (4–12 цифр) |
| `getAdminState` | — | всё для админки одним запросом: статус, все менеджеры (и неактивные), подразделения, пары, настройки |
| `saveManager` | `name, dept, active?, originalName?` | добавить менеджера или изменить: переименовать (`originalName`), перевести в другое подразделение, (де)активировать |
| `deleteManager` | `name` | убрать из справочника (история остаётся) |
| `importRoster` | `entries:[{name,dept}], deptTitles?, deactivateMissing?` | справочник из файла: новых добавляет, известных переводит; никого не удаляет |
| `saveDepartment` | `code, title?, leader?` | название подразделения и имя РГ |
| `importSnapshot` | `rows:[{name,count}], addUnknown?:[{name,dept}], allowDecrease?, requestId?` | загрузка счетов (накопительно за день). Всё или ничего: неизвестные имена → `unknown_managers`, уменьшение → `count_decreased` (если не разрешено) |
| `listSnapshots` / `listDays` | `limit?, importId?` | история (новые сверху) |
| `setPairs` | `pairs:[{left,right}]` | до 3 пар, каждое подразделение не более одного раза |
| `finishDay` | `requestId?` | завершить игровой день (см. выше); экранам уходит команда `finale` |
| `newPeriod` | — | новая неделя: звёзды 0, счётчики 0 |
| `setStars` | `rop, stars` | ручная поправка звёзд |
| `setSettings` | `daysPerPeriod` | дней в неделе (1–5) |
| `setDisplayKey` / `getDisplayKey` | `key?` | ключ экрана (без `key` генерируется случайный) |
| `command` | `type, args?` | показать на экранах: `fight {pairId,leftAvg,rightAvg,sample?}`, `finale` (демо), `confetti`, `celebrate` |

Ответ — `{ok: true, ...}` или `{ok: false, error}`: `invalid_pin`, `locked` (+`retryAfterSec`), `bad_request` (+`field`, `row`), `unknown_managers` (+`names`),
`count_decreased` (+`items`), `period_finished`, `no_pairs`, `duplicate_name`, `not_found`, `server_error` (+`detail`). После 5 неверных PIN за 10 минут API блокируется на 10 минут.
Записи берут блокировку скрипта; `requestId` защищает от дублей при повторной отправке (кэш на 10 минут). Команды анимаций живут в Script Properties (последние 10, свежее 10 минут), в таблицу не пишутся.

## Форматы файлов для админки

- **Загрузка данных** (каждые ~2 часа): `.xlsx`, `.csv` или текст из буфера; строка = «ФИО, число счетов от 20 минут на текущий момент» (накопительно за игровой день), заголовок не нужен.
  Совпадение по ФИО не зависит от регистра, «ё/е» и пробелов. Сотрудников, которых нет в файле, это не обнуляет.
- **Справочник** (разово и для массовых перестановок): столбец, где строка с названием подразделения (содержит код `СР1`…`СР9`, например `КЦПК_НП_СР_Тверь_СР1_ГБ`)
  открывает группу, а под ней идут ФИО её менеджеров. Либо два столбца «ФИО | код подразделения».

Файлы с реальными ФИО в репозиторий не кладутся (`*.xlsx`, `*.csv` в `.gitignore`).

## Проверка без деплоя

`Code.gs` прогоняется локально на имитации сервисов Google (`apps-script/test/gas-harness.mjs`):

```bash
cd game
npm run test:backend      # 36 тестов: PIN, справочник, загрузки, средние, день/неделя, команды, ключ экрана
npm run mock-backend      # тот же Code.gs по http://127.0.0.1:8787/exec (PIN 1234, 65 выдуманных сотрудников, данные в памяти)
```

Для dev-сборки игры и админки адрес подменяется параметром `?backend=http://127.0.0.1:8787/exec`; ключ экрана мока — `mock-display-key-1234`
(`http://127.0.0.1:8080/?backend=http://127.0.0.1:8787/exec#key=mock-display-key-1234`).
