# Запуск и эксплуатация

Проект **изолирован** от боевой игры «Отделы против дракона»: свой репозиторий `KonturProject/mortal-sales`, своя таблица, свой Apps Script, деплой защищён скриптом. Развёрнут 01.10.2026: сайт <https://konturproject.github.io/mortal-sales/>, админка `…/admin.html`. Ниже — как это устроено и как повторить с нуля (например, для второго офиса).

## 1. Локальная разработка

```bash
cd game
npm install
npm run mock-backend         # терминал 1: бэкенд на :8787 (PIN 1234, 65 выдуманных сотрудников, данные в памяти)
npm run dev                  # терминал 2: http://127.0.0.1:8080
```

| Что открыть | Адрес |
|---|---|
| Игра (с мок-бэкендом) | `http://127.0.0.1:8080/?backend=http://127.0.0.1:8787/exec#key=mock-display-key-1234` |
| Админка | `http://127.0.0.1:8080/admin.html?backend=http://127.0.0.1:8787/exec` (PIN 1234) |
| Игра без бэкенда (демо-данные) | `http://127.0.0.1:8080/` (по умолчанию `useMock: true`) |

Полезные параметры адреса (только dev-сборка): `?backend=…`, `?pollms=2000` (опрос раз в 2 с вместо 15). В любой сборке: `?quality=low|high`, `?scale=1.25`, `?fps=30`, `?idlefps=5`.

Сервер привязан к `127.0.0.1` (IPv4) намеренно: на некоторых машинах `localhost` указывает только на IPv6 и встроенный браузер туда не попадает.

Проверка боевой сборки как на GitHub Pages (из подпапки):

```bash
npm run build
npm run serve-dist           # http://127.0.0.1:8090/mortal-sales/  (+ admin.html)
```

## 2. Новый бэкенд (Google Таблица + Apps Script)

Делается в **новой** таблице и **новом** скрипте. Пошагово — [apps-script/README.md](../apps-script/README.md); коротко:

1. Создать пустую Google Таблицу, взять её ID из адреса.
2. В таблице: Расширения → Apps Script (привязанный скрипт), вставить `Code.gs`, заменить `REPLACE_WITH_NEW_SPREADSHEET_ID`; включить показ манифеста и вставить `appsscript.json`.
3. Обновить таблицу → меню **Mortal Sales → 1. Подготовить таблицу** (при первом запуске Google просит разрешение; создаст 6 вкладок с заголовками и начальными строками).
4. Меню **Mortal Sales → 2. Задать PIN администратора**: PIN вводится в окне Google, в коде его нет.
5. Deploy → New deployment → Web app: *Execute as — Me*, *Who has access — Anyone*. Скопировать `/exec`-адрес.
6. Вписать адрес в `game/public/config.json`: `{"appsScriptUrl": "https://script.google.com/macros/s/…/exec", "useMock": false}`.
7. Открыть админку → **Доступ → Создать ключ экрана** → ссылка для экрана.
8. **Сотрудники → Импорт справочника из файла** — загрузить «Распределение менеджеров по подразделениям».
9. **Пары и отделы** — проверить пары и (по желанию) вписать имена руководителей групп.
10. **День и неделя** — проверить длину недели и цель (по умолчанию 5 дней и 1,20).
11. Любое изменение `Code.gs` → Deploy → Manage deployments → ✏️ → *New version* (адрес не меняется).

Что стоит проверить при первом боевом запуске (на имитации Google это проверить нельзя):

- «Подготовить таблицу» создал вкладки, строка «Ключ»/«Значение» в `Настройки` заполнена;
- загрузка тестового файла записывает даты в `Снимки` в виде даты-времени (а не текста), а `Активен` — флажками/ИСТИНА-ЛОЖЬ;
- GET по `…/exec?key=…` в браузере возвращает JSON без окна входа Google; без `key` — `bad_display_key`;
- завершение дня и новая неделя работают на копии таблицы до боевого использования;
- время ответа 1–3 секунды (дольше — это нормально для «холодного» Apps Script, игра это учитывает).

## 3. Новый репозиторий и публикация

Репозиторий `KonturProject/mortal-sales` (публичный: бесплатные Pages работают только с публичным). Ветка `main` — исходники; сайт публикуется командой в ветку `gh-pages`:

```bash
cd game
npm run deploy               # сборка + публикация dist в ветку gh-pages (Pages включаются сами при первой публикации)
```

Для нового репозитория: `git remote add origin https://github.com/<аккаунт>/<репозиторий>.git` (пути в сборке относительные, `base: './'`, имя репозитория в них не зашито).

`npm run deploy` сначала запускает `tools/deploy-guard.mjs`: он откажется работать без `origin` и если `origin` указывает на репозиторий боевой игры. Адрес сайта — `https://<аккаунт>.github.io/<репозиторий>/`, админка — `…/admin.html`. Пути в сборке относительные, подпапка Pages ничего не ломает (проверено `serve-dist`).

Что попадёт в публичный репозиторий и сайт: код, фон `bg_arena.jpg`, спрайты, **демо-данные с выдуманными именами**. Звуки (`public/assets/audio/*`: голоса диктора и музыка) публикуются — так решил владелец. Не попадёт: файлы Excel/CSV, PIN и ключ экрана (они только в Script Properties). Адрес Web App в `config.json` публичен намеренно — без ключа экрана он ничего не отдаёт.

## 4. Экран в офисе

1. Открыть в браузере ссылку из «Доступ → Ключ экрана» (она выглядит как `…/index.html#key=…`). Ключ запомнится.
2. Режим киоска Chrome: `chrome --kiosk --autoplay-policy=no-user-gesture-required "<ссылка>"`. Флаг нужен для звука: без него браузер разрешает его только после клика; после перезагрузки звук включается по первому нажатию на экран, если был включён кнопкой.
3. Включить автозапуск браузера при входе в систему и отключить сон/заставку.
4. Экран сам переживает обрывы связи: в углу будет «офлайн · N мин», картинка остаётся, при возвращении связи всё продолжится без перезагрузки.
5. Звук по умолчанию выключен: один раз нажмите кнопку в правом нижнем углу экрана (🔇 → 🔊), выбор запоминается в браузере. Голоса и музыка грузятся с сайта (около 3 МБ).

Слабые компьютеры: игра сама выбирает качество (`low` — ≤ 4 логических ядер или ≤ 4 ГБ памяти: 30 кадров/с, буфер не больше 1,5×). В простое — 10 кадров/с. Проверить режимы: `?quality=low`.

## 5. Обслуживание

| Задача | Как |
|---|---|
| Новая неделя | админка → «День и неделя» → «Начать новую неделю» |
| Сменить PIN | админка → «Доступ» (или меню таблицы «Mortal Sales → Задать PIN администратора», если забыт) |
| Сменить ключ экрана | админка → «Доступ» → «Создать новый ключ», открыть новую ссылку на экране |
| Заменить фон | положить картинку 16:9 (лучше 1920×1080) в `assets-source/new-game/backgrounds/`, скопировать как `public/assets/sprites/bg_arena.jpg`, подобрать линии бойцов (`ARENA.LANES` в `Constants.ts`) |
| Изменить цель и длину недели | админка → «День и неделя → Настройки» |
| Подкрутить жёсткость боёв | `FIGHT_TUNING` в `systems/FightPlanner.ts` (пороги ярусов `tierEdges`, число ударов `baseHits`/`hitsSpan`, доверие `confidenceInvoices`) + тесты `npm run test:fight` |
| Добавить позы героев | положить PNG в `assets-source/new-game/animations/` и сообщить (подключается вручную, см. README той папки) |
| История и резервная копия | вкладки таблицы `Снимки`/`Дни` — полный журнал; версии таблицы хранит Google (Файл → История версий) |

## 6. Если что-то пошло не так

| Симптом на экране | Причина | Решение |
|---|---|---|
| «Ключ экрана ещё не создан…» | в Script Properties нет ключа | админка → «Доступ» → создать ключ |
| «Неверный ключ экрана…» | экран открыт по старой ссылке | открыть актуальную ссылку из «Доступа» |
| «Нет связи с сервером данных…» | нет сети, не тот адрес, Apps Script недоступен | проверить `config.json` и `/exec` в браузере |
| В углу «офлайн · N мин» | пропали ответы, картинка осталась прежней | дождаться связи, перезагрузка не нужна |
| Бой не начался после загрузки | рост не у пар на экране или значения не выросли (исправление) | посмотреть «Было → Станет» в предпросмотре и вкладку «День и неделя» |
| Бой не повторился после перезагрузки экрана | так задумано: первый ответ — исходное состояние | — |
| Финал не показан, но звёзды верные | экран был выключен >2 минут | так задумано, состояние верное |
| Пары не те | пары не сохранены / сохранены в процессе боя | сохранить заново; на экране пересадка после боя |
| Белый/пустой экран | ошибка загрузки скриптов | открыть консоль браузера (F12), обновить |
| Среднее отдела занижено, отдел «всегда проигрывает» | в штате числятся люди, которых нет на работе (отпуск, ушли) | снять «Активен» на вкладке «Сотрудники» — они перестанут делить сумму |
