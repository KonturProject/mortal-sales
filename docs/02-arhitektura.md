# Архитектура

Технический справочник: как устроен проект, где что лежит, какие решения приняты и почему. Правила игры — в [01-igra.md](./01-igra.md), работа админа — в [03-admin.md](./03-admin.md), запуск — в [04-zapusk.md](./04-zapusk.md).

## Общая схема

```
  Google Таблица  ◄────────────►  Apps Script Web App  ◄──────── админка (PIN)   src-admin/
  (6 вкладок,                     apps-script/Code.gs              ─ все изменения
  источник правды)                      ▲
                                        │ GET ?key=<ключ экрана>  каждые 15 с
                                        │
                                 игра (экран офиса)  src/
                                 DataPollingService ─► GameState ─► EventBus ─► ArenaScene + HUDScene
```

- **Игра только читает.** Любое изменение (счета, сотрудники, пары, день, неделя, настройки) проходит через админку и PIN.
- **Таблица — источник правды**, читаемая человеком; бэкенд при необходимости сам создаёт вкладки и заголовки.
- Экран и админка — **две отдельные страницы одного Vite-проекта**: `index.html` (Phaser) и `admin.html` (обычный DOM, без Phaser). Собираются в `game/dist`.

## Стек

Phaser 4.0, Vite 6, TypeScript 5.7 (strict + noUnused*), `read-excel-file` (чтение .xlsx в браузере, подгружается лениво), Google Apps Script (V8), Node ≥ 22.18 для тестов (запускает `.ts` напрямую). Единственная продакшн-зависимость, кроме Phaser, — `read-excel-file`; `npm audit --omit=dev` чист.

## Данные и бэкенд

### Вкладки таблицы

| Вкладка | Колонки (порядок важен, названия нет) | Содержимое |
|---|---|---|
| `Команда` | ФИО · Подразделение · Активен · За день · За неделю до сегодня | один ряд на менеджера |
| `Подразделения` | Код · Название · РГ · Звёзды · Побед · Поражений · Ничьих | шесть кодов по числу героев |
| `Пары` | № · Слева · Справа | до трёх пар |
| `Снимки` | Импорт · Время · День · ФИО · Подразделение · Счетов · Изменение | каждая загрузка, только добавляется |
| `Дни` | День · Неделя · № в неделе · Время · Подразделение · Счетов · Людей · Среднее · Пара · Итог · Звёзды после | завершённые дни |
| `Настройки` | Ключ · Значение | PeriodId, PeriodState, DayIndex, DayId, ImportSeq, DaysPerPeriod, TargetAvg, PeriodWinners, LastImport |

Правила: строки целиком не удаляются (только очищаются ячейки); коды подразделений принимаются в любом виде («СР1», «cp1», «СР 1»); потерянная вкладка создаётся заново; история читается только с хвоста (последние 4000 строк); имена сопоставляются без учёта регистра, «ё/е», пробелов и формы Unicode.

### Публичный ответ (GET)

```jsonc
{
  "ok": true,
  "period":  { "id": 12, "dayIndex": 2, "daysTotal": 5, "state": "active" },   // у закрытой недели ещё "winners": {"1":"СР1","2":"draw"}
  "pairs":   [ { "id": 1, "left": "СР1", "right": "СР3" } ],
  "targetAvg": 1.2,
  "leaders": [ { "rop": "СР1", "stars": 2, "staff": 12, "dayCount": 23, "periodCount": 61, "name": "Орлов Игорь Петрович" } ],
  "managers": [ { "name": "Фамилия Имя Отчество", "rop": "СР1", "day": 2, "period": 7 } ],   // только активные
  "lastImport": { "id": 7, "at": "…Z", "before": { "СР1": 10, … }, "after": { "СР1": 23, … } },   // суммы за день по подразделениям
  "commands": [ { "id": 41, "type": "finale", "args": { … }, "issuedAt": 1790000000000 } ],
  "serverNow": 1790000001234, "lastUpdated": "…Z"
}
```

Без верного `?key=` отдаётся только `{"ok":false,"error":"display_key_not_set" | "bad_display_key"}`. Ответ кэшируется на 10 с; любая запись сбрасывает кэш; пересборка идёт под блокировкой скрипта, чтобы GET не прочитал половину записи.

### Действия админа (POST, JSON как text/plain, PIN в теле)

Полная таблица — в [apps-script/README.md](../apps-script/README.md). Общие свойства:

- каждая запись под блокировкой скрипта, идемпотентна по `requestId` (кэш 10 минут);
- загрузка «всё или ничего»: неизвестные имена и уменьшившиеся значения отклоняются со списками, пока админ не решил, что с ними делать; ничего не пишется при отказе;
- текст в ячейках (имена, названия) отвергается, если начинается с `= + - @` (формула в таблице);
- счета — целые числа ≥ 0; пустое значение не считается нулём;
- PIN хранится солёным хешем в Script Properties; пять неверных PIN за 10 минут блокируют API на 10 минут;
- очередь команд анимаций — в Script Properties (последние 10 не старше 10 минут, не больше ~7,5 КБ), в таблицу команды не пишутся.

### Завершение дня и недели

`finishDay` под блокировкой: считает средние по активному штату → определяет победителя каждой пары → начисляет победителю звезду → пишет `Дни` → переносит «за день» в «за неделю до сегодня» и обнуляет день → увеличивает счётчики → при последнем дне решает матчи пар и закрывает неделю → кладёт в очередь команду `finale` с готовыми итогами. Состояние (звёзды, табло недели) корректно и без открытого экрана.

## Игра

### Сцены и поток событий

`Boot → Preloader → ArenaScene + HUDScene` (две параллельные сцены, общаются только через `EventBus`).

| Событие | Кто шлёт | Что означает |
|---|---|---|
| `DATA_UPDATED` | опрос | пришёл свежий статус (после обработки боёв и команд) |
| `FETCH_ERROR` | опрос | опрос не удался (с причиной) |
| `FIGHT_ROUND` | опрос | новый импорт, у этих пар вырос показатель; встаёт в очередь арены |
| `FINALE` | опрос (команда `finale`) | админ завершил день; встаёт в очередь арены |
| `ADMIN_COMMAND` | опрос | визуальная команда (конфетти, «все празднуют») |
| `FIGHT_START` / `FIGHT_END` | арена | раунд реально начался / закончился (баннер FIGHT!, разблокировка полос) |
| `BLOW` | арена | один удар (полоски движутся ступенями) |
| `FINALE_START` / `FINALE_PAIR` / `FINALE_END` | арена | финал начался / в этой паре загорается звезда победителя / закончился |

Порядок обработки одного ответа (`DataPollingService.process`): применить к `GameState` → найти бой (`FightPairs.fightPairsFor`) → разослать команды (первая сразу, чтобы `FINALE` дошёл до HUD раньше `DATA_UPDATED`) → `DATA_UPDATED`.

### Ключевые модули

| Файл | Роль |
|---|---|
| `systems/FightPlanner.ts` | чистая функция: средние → план ударов (ярус, число ударов, реакции). Тюнинг в `FIGHT_TUNING` |
| `systems/FightPairs.ts` | чистые функции: какие пары дерутся после импорта; проверка формы статуса и финала |
| `systems/FightDirector.ts` | план → хореография пары (шаг к центру, удары, реакция, возврат; финал дня) |
| `objects/Fighter.ts` | боец: все движения как `Promise` («эпохи» отменяют прерванное движение) |
| `scenes/ArenaScene.ts` | фон, шесть бойцов, рассадка по парам, очередь раундов и финалов, табло недели |
| `scenes/HUDScene.ts` | лайфбары, звёзды, рейтинг, баннеры, статус, звук; блокировки полос на время анимации |
| `objects/PairLifebar.ts`, `StarRow.ts`, `ManagerBoard.ts` | элементы HUD |
| `systems/DataPollingService.ts` | опрос (дублирующий запрос против медленного «хвоста» Apps Script), ключ экрана, команды |
| `core/GameState.ts`, `EventBus.ts`, `Constants.ts`, `Async.ts` | состояние, события, вся геометрия и тайминги, `sleep/tweenTo/hitStop` |
| `core/Quality.ts`, `PowerSaver.ts` | качество по устройству и частота кадров (простой 10 кадров/с) |

### Принципы, которые нельзя ломать

1. **Базовая линия.** Первый ответ после загрузки страницы — только исходное состояние: без боя, без повтора финала, без старых команд.
2. **Анимации удерживают цифры.** Опрос, принёсший событие, приносит и новые цифры; HUD держит полосы и звёзды на картине «до», пока арена не доиграет (счётчики блокировок, а не флаги).
3. **Очередь.** Бои и финалы идут строго по одному; баннеры привязаны к реальному старту, не к приходу события.
4. **Прерванное не продолжается.** Каждое движение бойца начинается с `halt()` и после каждого `await` проверяет, не заменили ли его.
5. **Всё конечное.** Ни одного бесконечного твина и случайных таймеров на объект: иначе слабые ноутбуки не уходят в режим простоя. Покачивание в простое — одно общее расписание.
6. **Тексты** создаются с `resolution: GAME.RENDER_SCALE` (`hudText()`); никакого свечения и теней у персонажей.
7. **Доверять нельзя ничему из таблицы:** в админке DOM строится текстовыми узлами (`h()`), `innerHTML` не используется.

### Геометрия

Логические 1280×720; буфер холста = ×`RENDER_SCALE` (1…2 по размеру экрана, на слабых устройствах не выше 1,5). Фон `bg_arena.jpg` даёт узкий пол (нижние ~20 %), поэтому три линии бойцов (`ARENA.LANES`: y 614 / 657 / 700, масштаб 0,64 / 0,75 / 0,86) и панели рейтинга на небе. Пары встречаются в разных точках (`clashX` 640 / 470 / 810), чтобы бойцы соседних линий не стояли друг на друге. Менять фон — значит подбирать эти числа заново.

## Админка

Простой DOM без фреймворка. `main.ts` держит PIN в памяти и текущее состояние (`getAdminState`), строит вкладки (`tabs/*.ts`), общий контекст `Ctx` (`call`, `refresh`, `guard`, `report`, `setStatus`) и превращает коды ошибок бэкенда в понятные сообщения. `parse.ts` (чистый, покрыт тестами) разбирает .xlsx/.csv/вставленный текст в строки загрузки и справочника. Страница на телефоне работает: таблицы прокручиваются внутри блока.

## Приватность и безопасность

| Тема | Решение |
|---|---|
| Имена и результаты сотрудников | Публичный GET отдаётся только по «ключу экрана» (случайный, меняется из админки); на экране — «Фамилия И.О.» |
| Файлы с реальными ФИО | не в git (`*.xlsx`, `*.xls`, `*.csv` в `.gitignore`); мок использует выдуманные имена |
| PIN | солёный хеш в Script Properties, блокировка подбора, не передаётся в URL |
| Формулы в таблице | текст, начинающийся с `= + - @`, отклоняется |
| Телеметрия | шаблонный `log.js` (запрос на `gryzor.co` при `dev`/`build`) удалён |
| Деплой | `deploy-guard.mjs` не даст опубликовать в репозиторий боевой игры |
| Музыка и голоса | `public/assets/audio/*` в репозитории и на сайте — решение владельца от 04.10 (некоммерческий офисный экран); исходники кладутся в `sounds/` (не в git) |

## Известные ограничения

- Бэкенд проверен на имитации Google, не на настоящих Таблицах (см. [06-проверка](./06-proverka.md)).
- Ошибочное «Завершить день» нельзя отменить (звёзды правятся вручную, счётчики — в таблице).
- Экран, который был выключен во время финала, его не покажет (состояние при этом верное). Команды живут 2 минуты по часам сервера.
- Две загрузки между двумя опросами экрана (15 с) сливаются в один бой.
- Позы есть только для ударов (у Скруджа 4, у остальных по 3); получение удара, падение, полёт и победа изображаются движением.
- Звук на экране включается кнопкой один раз; без флага `--autoplay-policy=no-user-gesture-required` после перезагрузки нужен клик по экрану.
